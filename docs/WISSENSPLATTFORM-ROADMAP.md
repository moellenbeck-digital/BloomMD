Die M1-Closed-Beta für macOS hat Vorrang. / **Direction, not a release plan.** This inventory records the ten themes of the expanded product vision. An existing reference is evidence of a document or issue, not a claim that the whole capability has shipped. The BloomMD Roadmap Board owns tasks, status, and priority. Milestones W0–W3 group verifiable scope decisions, not feature or date commitments. The M1 macOS closed beta takes priority.

BloomMD bleibt ein lokal nutzbarer visueller Workspace für portable Markdown-Dateien. Die [README](../README.md) beschreibt den heutigen Produktkern, die [Vision](WISSENSPLATTFORM-VISION.md) seine Grundsätze und dieses Dokument den möglichen Ausbau. Eine Ausbaustufe braucht eine konkrete Nutzerfrage, Abnahmekriterien, Kapazität und ein eigenes Release-Ticket, bevor sie als Lieferung geplant wird.

BloomMD remains a locally usable visual workspace for portable Markdown files. The [README](../README.md) describes today's product, the [vision](WISSENSPLATTFORM-VISION.md) its principles, and this document a possible expansion. A stage needs a concrete user need, acceptance criteria, capacity, and its own release issue before delivery is planned.

### Abhängigkeiten und Planung

1. **Jetzt:** Markdown-Kern und [Learnings-Pilot #116](https://github.com/moellenbeck-digital/BloomMD/issues/116) anhand echter Nutzung prüfen. M1 und laufende Release-Arbeit behalten Vorrang.
2. **Danach prüfen:** Sync-Grundlage und eine begrenzte lesende Integration; die Quellhoheit und das Konfliktmodell müssen vorher klar sein.
3. **Vor Schreibzugriff und Suche über mehrere Bereiche:** Identität, widerrufbare Rechte und Audit belegen. ACL-bewusste Suche darf keine Inhalte außerhalb des erlaubten Bereichs liefern.
4. **Später nach Nachweis:** allgemeiner Wissenslebenszyklus, Agenten-Workflows und größere Governance-Funktionen. Betrieb und Transparenz begleiten jede Stufe.

Diese Reihenfolge ist eine Abhängigkeitskarte, keine Termin- oder Kapazitätszusage. [W0](https://github.com/moellenbeck-digital/BloomMD/milestone/4) umfasst Pilot und Wissensmodell (#116, #259), [W1](https://github.com/moellenbeck-digital/BloomMD/milestone/5) Sync und erste Quelle (#261, #264), [W2](https://github.com/moellenbeck-digital/BloomMD/milestone/6) Rechte und Suche (#262, #260) und [W3](https://github.com/moellenbeck-digital/BloomMD/milestone/7) die späteren Themen (#263, #265–#268). Bestehende Implementierungstickets werden wiederverwendet. Zusätzliche Implementierungstickets und ein Release-Meilenstein mit Versionen, Artefakten, Tests, Dokumentation und Kommunikation folgen erst aus der Scope-Entscheidung.

### Dependencies and planning

1. **Now:** Test the Markdown foundation and [learnings pilot #116](https://github.com/moellenbeck-digital/BloomMD/issues/116) in real use. M1 and current release work retain priority.
2. **Evaluate next:** Sync foundations and one limited read-only integration, after source ownership and conflicts are defined.
3. **Before cross-scope writes and search:** Prove identity, revocable rights, and audit. Permission-aware search must never return unauthorized content.
4. **After evidence:** Extend the lifecycle, agent workflows, and governance. Operations and transparency accompany every stage.

This sequence maps dependencies without dates or capacity commitments. [W0](https://github.com/moellenbeck-digital/BloomMD/milestone/4) covers the pilot and knowledge model (#116, #259), [W1](https://github.com/moellenbeck-digital/BloomMD/milestone/5) sync and the first source (#261, #264), [W2](https://github.com/moellenbeck-digital/BloomMD/milestone/6) rights and search (#262, #260), and [W3](https://github.com/moellenbeck-digital/BloomMD/milestone/7) the later themes (#263, #265–#268). Reuse existing implementation issues. Add new implementation issues and a release milestone with versions, artifacts, tests, documentation, and communication only after the scope decision.
