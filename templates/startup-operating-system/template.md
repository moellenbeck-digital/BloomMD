# Startup Operating System <!-- bloommd:id=startup-os-root -->

A compact operating system for a small SaaS team that needs one shared map for product, market and execution.

## Vision <!-- bloommd:id=startup-os-vision -->

Build a local-first product that lets knowledge workers understand large Markdown collections visually without giving up ownership of their files.

## Product <!-- bloommd:id=startup-os-product -->

- Core promise: turn Markdown into an editable map.
- Free entry: local templates and demo.
- Paid expansion: pro workflows, sync, desktop polish and team features.

## Customers <!-- bloommd:id=startup-os-customers -->

Primary users are developers, researchers, writers and Obsidian power users who already trust Markdown and do not want another proprietary workspace.

## Positioning <!-- bloommd:id=startup-os-positioning -->

BloomMD is not another notes app. It is a visual layer over files users already own.

## Marketing <!-- bloommd:id=startup-os-marketing -->

- Launch with templates on Reddit, X and GitHub.
- Publish short demos showing Markdown turning into maps.
- Use Obsidian plugin as a high-intent acquisition channel.

## Sales <!-- bloommd:id=startup-os-sales -->

Start self-serve. Founder-led sales can target software teams, agencies and research groups once templates and demo flows prove demand.

## Metrics <!-- bloommd:id=startup-os-metrics -->

- Demo opened
- Template opened
- Own Markdown tried
- Download clicked
- Account created
- Obsidian plugin clicked

## Roadmap <!-- bloommd:id=startup-os-roadmap -->

- Template library
- Public demo
- GitHub polish
- Obsidian beta
- Desktop packaging

## Decisions <!-- bloommd:id=startup-os-decisions -->

- Markdown remains source of truth.
- Templates are static files, not proprietary data.
- Analytics never includes document content.

## Risks <!-- bloommd:id=startup-os-risks -->

- Users may compare BloomMD to full PKM suites instead of a focused visual layer.
- Desktop install flow must be clearer before broad launch.
- The Obsidian plugin must avoid any perception of data exfiltration.
